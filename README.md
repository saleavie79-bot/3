# بوابة بيانات دخول الطلاب

مشروع Node.js لعرض بيانات دخول الطالب بعد مطابقة **الاسم الكامل والرقم القومي** مع سجل واحد في قاعدة البيانات.

## مكونات المشروع

- `public/`: الواجهة العربية المتجاوبة.
- `server.js`: خادم API مع تحديد معدل المحاولات.
- `src/security.js`: تطبيع الأسماء، HMAC للرقم القومي، وتشفير كلمات المرور.
- `scripts/init-db.js`: إنشاء جدول قاعدة البيانات.
- `scripts/import-excel.js`: استيراد ملف Excel محليًا دون رفعه إلى GitHub.
- `scripts/generate-secrets.js`: إنشاء مفاتيح التشفير.

## تنبيه خصوصية

لا ترفع ملف Excel، أو ملف `.env`، أو مفاتيح التشفير، أو نسخة من قاعدة البيانات إلى مستودع GitHub. لا تضع الأسرار داخل ملفات الواجهة. رقم الهوية لا يُحفظ كنص صريح في قاعدة البيانات؛ يُحفظ بصمة HMAC، وتُشفّر كلمة المرور باستخدام AES-256-GCM. تبقى أسماء الطلاب وأكوادهم وأسماء المستخدمين ظاهرة داخل قاعدة البيانات، لذا يجب تقييد الوصول إلى قاعدة البيانات والخادم.

## متطلبات النشر

- حساب GitHub لحفظ كود المشروع.
- خدمة PostgreSQL مُدارة (يمكن البدء بخطة مجانية إن كانت متاحة وقت الإعداد).
- خدمة Node.js لاستضافة الخادم. GitHub Pages وحده لا يشغّل هذا الخادم.
- مفاتيح سرية ثابتة محفوظة في إعدادات الخدمة، وليست في GitHub.

لا تعتمد على نظام ملفات مؤقت لتخزين قاعدة البيانات. استخدم PostgreSQL مُدارًا مع نسخة احتياطية مناسبة. الخطط المجانية وحدودها قد تتغير، وقد تتوقف الخدمة عند الخمول.

## 1. تجهيز قاعدة PostgreSQL

أنشئ قاعدة بيانات PostgreSQL لدى مزود موثوق. احتفظ بعنوان الاتصال `DATABASE_URL` بسرية، وفعّل TLS. أنشئ ملفًا محليًا اسمه `.env` انطلاقًا من `.env.example`، ولا ترفعه إلى GitHub.

ثبّت Node.js 20 أو أحدث، ثم نفّذ من مجلد المشروع:

```bash
npm install
node scripts/generate-secrets.js
```

انسخ المفتاحين الناتجين إلى `.env` كما هما، وإلى متغيرات البيئة في خدمة الاستضافة. **استخدم القيم نفسها عند الاستيراد والتشغيل، ولا تغيّرها بعد الاستيراد**؛ تغييرها يمنع التحقق من أرقام الهوية وفك تشفير كلمات المرور الموجودة.

أضف `DATABASE_URL` إلى `.env`، ثم نفّذ:

```bash
node scripts/init-db.js
```

## 2. استيراد ملف الطلاب بأمان

ضع ملف Excel على جهازك المحلي فقط. نفّذ:

```bash
node scripts/import-excel.js "/المسار/إلى/AI INFO.xlsx"
```

يقرأ البرنامج ورقة `بيانات الطلاب` إن وجدت، ويطابق الأعمدة: `اسم الطالب`، `الكود`، `اسم المستخدم`، `كلمة المرور`، `الرقم القومي`. لا يطبع القيم السرية في الطرفية. راجع رسالة الاستيراد لمعرفة عدد السجلات المستوردة والمتجاوزة.

يستخدم الاستيراد `ON CONFLICT` لتحديث السجل ذي بصمة الرقم القومي نفسه، ولا يحذف بقية السجلات. افحص ملف Excel الأصلي يدويًا للتأكد من صحة كل كلمة مرور؛ البرنامج لا يستطيع معرفة إن كانت بيانات المصدر صحيحة.

## 3. تشغيل محلي

```bash
npm start
```

ثم افتح `http://localhost:3000`.

## 4. رفع الكود إلى GitHub

1. أنشئ مستودعًا جديدًا **خاصًا (Private)**.
2. لا تضف ملف Excel إلى المستودع.
3. ارفع ملفات المشروع فقط، مع التأكد من أن `.env` مستثنى بواسطة `.gitignore`.
4. اربط مستودع GitHub بخدمة استضافة Node.js.

حتى مع مستودع خاص، لا تحفظ أسرار التشغيل أو بيانات الطلاب فيه.

## 5. إعداد متغيرات البيئة على خدمة الاستضافة

أضف هذه المتغيرات في لوحة تحكم الخدمة:

- `NODE_ENV=production`
- `DATABASE_URL` — عنوان PostgreSQL.
- `NATIONAL_ID_HMAC_KEY` — مفتاح HMAC بطول 64 خانة hex.
- `PASSWORD_ENCRYPTION_KEY` — مفتاح تشفير بطول 64 خانة hex.
- `PGSSL=true`

أمر البدء: `npm start`. يجب أن تكون مفاتيح التشفير هي نفسها المستخدمة في الاستيراد المحلي.

## ملاحظات أمنية

- حد المحاولات الحالي 8 محاولات لكل عنوان IP خلال 15 دقيقة. راقب إساءة الاستخدام، وفكّر في إضافة CAPTCHA أو طبقة حماية أخرى عند الحاجة.
- الرد عند عدم التطابق لا يوضح هل الاسم أو الرقم القومي هو الخطأ.
- تطبيع الاسم يتجاهل فروقًا شائعة في الهمزات والتشكيل والمسافات والياء والألف المقصورة؛ لكنه لا يستخدم تخمينًا ضبابيًا قد يطابق طالبًا آخر.
- لا يمكن اعتبار الرقم القومي وحده وسيلة مصادقة قوية. لأن البوابة تعرض كلمات مرور، يفضّل أن تكون محمية بطبقة إضافية مناسبة إذا أمكن، مع إتاحة الوصول للطلاب المستهدفين فقط.
- لا تسجل طلبات البحث أو الأرقام القومية أو كلمات المرور في سجلات التطبيق.
- استخدم HTTPS فقط في النشر الفعلي.
- عند تغيير قاعدة البيانات أو المفاتيح، اختبر الاستعادة والتشغيل قبل نشر التحديث للطلاب.


## إصلاح رسالة `Unexpected token 'T' ... is not valid JSON`

هذه الرسالة تعني أن `/api/lookup` أعاد صفحة HTML أو نصًا بدل JSON. الواجهة الآن تعرض رسالة مفهومة بدل خطأ JSON الخام، لكن البحث لن يعمل على GitHub Pages وحده. شغّل خادم Node.js مع قاعدة PostgreSQL وانشر الخادم والواجهة معًا. اختبر `https://YOUR-HOST/api/health`؛ يجب أن يرجع JSON يحتوي على `status: ok`.

## إصلاح نشر Vercel

- تأكد أن **Root Directory** في إعدادات Vercel يشير إلى مجلد `student-login-portal` الذي يحتوي مباشرة على `package.json` و`server.js` ومجلد `src` ومجلد `api`.
- تأكد من وجود `src/security.js` و`api/lookup.js` في GitHub، مع مراعاة الأحرف الكبيرة والصغيرة.
- أضف متغيرات البيئة `DATABASE_URL`, `NATIONAL_ID_HMAC_KEY`, `PASSWORD_ENCRYPTION_KEY`, و`PGSSL` في Vercel ثم أعد النشر.
- اختبر `/api/health`؛ يجب أن يعيد JSON بحالة `ok` بعد إعداد قاعدة البيانات.
